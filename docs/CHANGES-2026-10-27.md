## 2. 커밋된 변경 (`eeabc55` feat: ERD 기준으로 DB 모델·SPEC 정리)

### 2.1 `app/db/models.py`

팀 ERD에 맞춰 테이블을 다시 정의했다. 연결이나 테이블 생성은 하지 않는다.

| 테이블 | 주요 내용 |
|---|---|
| `sources` | 수집 게시글 원문. `UNIQUE (site, post_id)`, `posted_date DATE`, `attachments JSONB`, `collected_at`은 `clock_timestamp()` |
| `patterns` | 수법 카드. `triggers TEXT[]`, `example_messages JSONB`(`text`·`type`·`source_post_id`), `embedding vector`, `is_active` |
| `pattern_sources` | 수법 카드↔게시글 다대다. 복합 기본키 |
| `indicators` | 정규화한 악성 단서. `UNIQUE (type, value_normalized)`, type은 `domain`·`url`·`phone`·`app_name` |
| `official_links` | 공식 도메인. `UNIQUE (domain)`, 검증 출처·시각은 NULL 허용 |
| `verdict_logs` | 판정 기록. 근거 ID는 `BIGINT[]` |

- `entities`, `pattern_indicators` 테이블은 없앴다. 지표는 수법 카드와 직접 연결하지 않는다.
- `tests/test_db_models.py`를 같은 계약으로 고쳤다.

### 2.2 `SPEC.md` 1~4장

- `entities` → `indicators`·`official_links`로 교체.
- 유사 검색 대상을 `cases`에서 **활성 `patterns`**로 변경. `cases`는 신고·관리자용으로만 남기고 임베딩하지 않는다.
- 판정 기록(`verdict_logs`) 단계(1.3의 7번, 테스트 A-26) 추가.
- 2.5.1~2.5.7에 테이블별 정의 추가, 재색인 명령 `reindex_patterns` 명시.
- 응답 필드 `matched_cases`는 이름을 유지하고 의미를 "반환된 수법 카드 수"로 바꿨다.

### 2.3 `.gitignore`

- 수집 폴더 `collector/`를 Git에서 제외.

### 3.2 동작

**임베딩 (`embedding.py`, SPEC 2.8)**
- 모델: `text-embedding-3-small`, 1536차원.
- 응답이 1536차원이 아니거나 NaN·무한대·영벡터·숫자가 아닌 값이면 실패(`EmbeddingError`).
- 응답 모델명 불일치, 순번·개수 오류, 연결 오류·timeout도 실패. 오류 메시지에 API 키를 넣지 않는다.
- 수법 카드 임베딩 문구는 `수법 → 설명 → 사칭 대상 → 유도 행동 → 위험 신호 → 예시 문자` 순서로 만든다(`pattern-text-v1`). 이 구성을 바꾸면 전체 재색인이 필요하다.

**재색인 (`reindex_patterns.py`, SPEC 2.8.3)**
- `is_active`이고 `embedding IS NULL`인 카드만 50개씩 임베딩한다.
- 외부 호출 중에는 트랜잭션·행 잠금을 잡지 않는다. 저장 직전에 카드를 다시 읽어, 그사이 내용이 바뀌었거나 벡터가 채워졌으면 저장하지 않는다.
- 실패한 배치의 벡터는 바꾸지 않고 나머지를 계속한다. 실패가 있으면 종료 코드 1.

```powershell
.venv\Scripts\python.exe -m app.commands.reindex_patterns --dry-run   # 대상만 출력, 외부 호출 없음
.venv\Scripts\python.exe -m app.commands.reindex_patterns             # 실제 임베딩
```

**유사 수법 검색 (`retriever.search_patterns`, SPEC 2.7)**
- 활성 수법 카드 전체를 대상으로 n-gram(Jaccard ≥ 0.35)과 pgvector(코사인 유사도 ≥ 0.80)를 각각 계산한다.
- n-gram은 ID 기준 500개씩 끝까지 순회하며, 카드 점수는 `summary`와 예시 문자 중 최댓값이다. 마스킹 표기(`OOO` 등)는 계산에서 뺀다.
- 두 결과를 RRF(`Σ 1/(60+순위)`)로 합쳐 최대 5개, 동점은 ID 오름차순.
- PostgreSQL에서는 읽기 전용 REPEATABLE READ 스냅샷과 남은 예산에 맞춘 `statement_timeout`을 쓴다. 전용 Session을 넘겨야 한다.
- 예외 대신 검색 상태를 돌려준다.

| 상황 | status / coverage | reason_code | matched_cases |
|---|---|---|---|
| 정상 완료 | completed / complete | null | 반환 수 |
| 활성 카드 0개 | completed / complete | null | 0 |
| 활성 카드 벡터 누락 | limited / limited | `vector_missing` | null |
| 저장 벡터 차원 불일치·영벡터 | limited / limited | `vector_invalid` | null |
| 5초 예산 초과 | limited / limited | `time_budget` | null |
| DB 오류 | failed / unknown | `db_error` | null |
| 질의 벡터 오류 | failed / unknown | `embedding_invalid` | null |
| 질의 벡터 없음(문자 전용) | limited / limited | `text_only` | null |

### 3.3 테스트

- 명령: `.venv\Scripts\python.exe -m pytest`
- 결과: **212개 통과, 1개 건너뜀** (기존 166개 + 신규 46개). 건너뛴 1개는 전용 pgvector DB가 필요한 기존 테스트.

## 5. 측정 결과 요약 (가상 문자 12건, 1회 실행)

### 5.1 유사도

- 스미싱 7건 모두 벡터 1위 카드는 맞는 수법이었다. 다만 유사도는 0.35~0.55로 **임계값 0.80을 하나도 넘지 못했다.**
- n-gram 최고값은 0.15로 임계값 0.35에 크게 못 미쳤다. 예시 문자를 거의 그대로 쓴 경우만 걸릴 것으로 보인다.
- 정상 택배 문자도 택배 사칭 카드와 0.416이 나와, 임계값 하나로 스미싱과 정상을 깔끔히 나누기 어렵다.
- 추정 원인: 카드 벡터를 긴 문구(설명+신호+예시)로 만들어 짧은 문자와의 점수가 희석된다.

### 5.2 LLM까지 거친 판정

| 조건 | 스미싱 7건 | 정상 5건 |
|---|---|---|
| 카드 없음 | RISK 3, UNKNOWN 4 | UNKNOWN 5 |
| 카드 넣음 (임계값 0.45 가정) | 같음 | 같음 |

- 오탐은 없었지만 정상 문자도 SAFE가 하나도 나오지 않았다.
- 놓친 스미싱 4건 중 3건이 링크·번호 없는 문자(지인 사칭, 수사기관, 카드발급)였다. 신호 목록에 해당 수법이 없어 LLM이 신호를 0~1개만 골랐다.
- 우리은행 시연 관련 문제 2가지:
  - 스킴 없이 적힌 `wooribank.com`을 추출하지 못한다.
  - `www.wooribank.com`은 `official_links`의 `wooribank.com`과 일치하지 않는다(호스트 완전 일치 규칙).

표본이 작아 확정 수치로 쓰지 않는다. 임계값·규칙 변경 전에 문자를 늘려 다시 측정한다.

| 판정 | risk_level | guide_type | 조건 |
|---|---|---|---|

## 7. 팀원 확인이 필요한 것

- **판정 개편으로 사람이 쓴 테스트를 수정했다**(승인 받음): `tests/test_decision.py`·`tests/test_llm_judge.py`(최민성), `tests/test_extractor.py`·`tests/test_pipeline_harness.py`(jiineom). LLM 응답 형식과 판정 기대값이 바뀌었다.
- **`tests/test_config.py`는 로컬 `.env`를 읽는다.** `.env`에 `DATABASE_URL`이 있으면 "설정이 없으면 None" 테스트가 실패하고, 실패 메시지에 접속 문자열이 그대로 출력된다. 테스트가 `.env`를 막도록 고쳐야 한다.
- **`docs/STATUS.md`와 다른 점**
  - 수집 테이블 이름은 `source`가 아니라 `sources`이며 현재 34건이다.
  - STATUS는 `Vector(1536)` 명시라고 적었지만, 현재 모델과 DB는 차원 없는 `vector`다.
  - STATUS는 환경 변수를 `LLM_*`·`EMBEDDING_*`로 통일한다고 했지만, `llm_judge.py`와 `.env.example`은 아직 `OPENAI_API_KEY`·`OPENAI_MODEL`을 쓴다. 지금은 같은 키를 `OPENAI_API_KEY`와 `EMBEDDING_API_KEY`에 두 번 넣어야 한다.

## 8. 로컬에서 재현하기

1. `.env.example`을 복사해 `.env`를 만들고 키·DB 주소를 직접 채운다. `.env`는 Git에 올라가지 않는다.
2. `.venv\Scripts\python.exe -m pytest`로 테스트를 확인한다.
3. 수법 카드 벡터가 비어 있으면 `reindex_patterns`를 실행한다. 15개 기준 비용은 1원 미만이다.
